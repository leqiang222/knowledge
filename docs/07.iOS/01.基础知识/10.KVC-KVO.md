# KVC-KVO

### KVC原理 

KVC（Key-value coding）键值编码，单看这个名字可能不太好理解。其实翻译一下就很简单了，就是指iOS的开发中，可以允许开发者通过Key名直接访问对象的属性，或者给对象的属性赋值。 

这样做最主要的好处是把访问和改变属性的动作放在了运行时，不需要再编译时确定。

但是也造成了硬编码。

- KVC可以给对象的私有变量赋值，比如UITextField的占位文字颜色，
```objectivec
// iOS11及以上会闪退了
[field setValue:UIColor.redColor forKeyPath:@"_placeholderLabel.textColor"]; 
```
- 用于字典转模型(MJExtension框架)
  - runtime获取对象全部Ivar属性字符串，通过KLV实现属性赋值

### KVO原理
KVO（key-value observing）键值观察，是苹果提供的一套事件通知机制 <br>
作用：允许对象监听另一个对象特定属性的改变，并在改变时接收到事件。

#### 使用KVO分为三个步骤： 
1.通过`addObserver:forKeyPath:options:context:`方法注册观察者，观察者可以接收keyPath属性的变化事件。<br>
2. 在观察者中实现`observeValueForKeyPath:ofObject:change:context:`方法，当keyPath属性发生改变后，KVO会回调这个方法来通知观察者。<br>
3. 当观察者不需要监听时，可以调用`removeObserver:forKeyPath:`方法将KVO移除。一般在delloc里调用。

#### KVO的底层实现、本质

1. 当一个对象使用了KVO监听，系统会通过Runtime动态创建一个该类的子类（比如监听Person类，底层会创建NSKVONotifying_Person子类），并且把该对象的isa指向这个子类。  
2. 子类拥有自己的set方法实现  <br>
   2.1.  假设被观察的属性名是`name`，若父类里有`setName:`，子类会重写`setName:`  
3. 子类set方法实现内部会顺序调用`willChangeValueForKey`方法、`父类的setter`方法实现、`didChangeValueForKey`方法， 
4. 而`didChangeValueForKey`方法内部又会调用监听器的`observeValueForKeyPath:ofObject:change:context:`监听方法。

#### 如何手动触发KVO

被监听的属性的值被修改时，就会自动触发KVO。如果想要手动触发KVO，则需要我们自己调用**willChangeValueForKey和didChangeValueForKey**方法即可在不改变属性值的情况下手动触发KVO，并且这两个方法缺一不可。
